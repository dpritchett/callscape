# Architecture — callscape

## Ground rules

1. **Test the pure core.** Selection, layout and encoding live in one pure function,
   `place(graph, view)`, that takes plain data and returns plain data. Every behaviour
   worth trusting is tested there, not through the renderer. Functions that read ambient
   state (a clock, a camera, the DOM) take it as an argument so they can be tested
   without one.
2. **Determinism is a product requirement, not a nicety.** The same graph and view must
   produce byte-identical placement, in any input order. A layout that shuffles between
   runs cannot be compared to itself, screenshot-tested, or reasoned about. There is a
   test that pins this; keep it passing.
3. **Commit early and often.** Small verified changes, committed and pushed promptly.
4. **Fast static analysis.** `go vet`, `go test`, `golangci-lint`, `tsc --noEmit` and
   `vitest`. If a check gets slow and low-value, drop it.
5. **Pre-commit checks via lefthook.** Checks run where the code runs. `make hooks`
   installs them, once per clone.
6. **One source of truth per check.** lefthook calls `make` targets, and `make check`
   runs everything lefthook runs. Nothing is defined in two places.
   There is deliberately no CI. One committer, one machine, no users — a hosted runner
   would be a second environment to keep green with nobody on the other side of it.
   Revisit the day a stranger might `go install` this or a second machine touches it;
   that is when a neutral arbiter starts having a constituency. There is a
   `.github/workflows/ci.yml` in the history, added early and removed for the reason
   above — it is gone from the tree on purpose, not by accident.
7. **Config is a closed struct.** An unknown field in `view.json` is an error, not
   something to ignore. A typo in a config file should be loud.
8. **Ten-minute rule.** If a decision would take more than ten minutes, take the boring
   option and record it in `DECISIONS.md` with one line on what was rejected. That file
   is the log; this one is the ground rules.

## System architecture

Two halves, one repo, connected by a JSON file on disk.

```
cmd/callscape-dump/      # Go: module -> graph.json
web/src/
  placement.ts        # (graph, view) -> PlacedNode[]  — pure, no three.js, no DOM
  select.ts           # occupant filtering: package globs, minFanIn, top-N
  layout.ts           # districts on a ring, symbols in a grid
  view.ts             # view.json parsing, closed struct
  world.ts            # three.js objects from a Placement — drawing only
  controls.ts         # camera, behind a Controller interface
  labels.ts           # canvas-texture sprites, sized in screen pixels
  main.ts             # wiring, polling, HUD
web/public/
  graph.json          # generated by `make dump`; untracked, a module-sized blob
  graph.default.json  # generated by `make sample`; this repo, tracked, what a clone flies
  view.json           # hand-edited; the live control surface
  badges/<host>/<owner>.png   # optional; the module's mark, hung outside the shell
```

**The dump side** loads a module with `go/packages` and emits one node per top-level func
or method declared in that module, plus an edge per statically resolved call between two
such nodes. Fan-in and fan-out are computed from the edge list before writing.

**The view side** polls both JSON files every 400ms and diffs the raw text. A change to
either rebuilds the scene; neither touches the camera. Vite's watcher is told to ignore
`public/*.json` because a public-dir change triggers a full page reload, and a reload
resets the camera — which would destroy the edit loop the project exists to demonstrate.

**The seam is plain data.** `world.ts` does no arithmetic; `placement.ts` knows nothing
about three.js. Anything interesting enough to get wrong belongs on the pure side.

## Known limits

- **Interface calls resolve to the interface method**, not the implementation. On
  gitlab-kiosk only 4 of 67 drawn edges cross a package boundary as a result. This is a
  measurement of what static resolution can see, and v0 reports it rather than working
  around it. Anything that changes it needs a decision recorded first — it is the
  headline result.
- **The renderer is verified by looking at it.** No automated browser has loaded the
  page. Tests cover the pure core and the label sizing math only.
- **`callscape-dump` runs the Go toolchain against its target.** `go/packages` shells out to
  `go list`, which can fetch dependencies, honour a `toolchain` directive and preprocess
  cgo. Point it only at code you would already run a build on.
- **The dev server binds the LAN** so the page can be flown from a phone, and **the
  endpoints that make that interesting to a stranger are off by default.** `UNSAFE_ENABLE_REMOTE_CONTROL=true`
  — `make dev-remote` — registers `/__cue`, `/__shot` and `/__src`; without it they are not
  routes, rather than routes answering 403, so there is nothing to probe. The containment
  in `srcpath.ts` applies either way: the flag decides who reaches an endpoint, those
  functions decide what it can do once reached.

## Scope

`HANDOFF.md` lists the non-goals verbatim, and they still hold: no LSP or gopls
integration, no daemon, no database, no persistence beyond the two JSON files, no
multi-language support, no UI framework. If a feature does not fit in "dump a graph" or
"fly through a graph", that is a signal it does not belong rather than a reason to add a
third thing.
